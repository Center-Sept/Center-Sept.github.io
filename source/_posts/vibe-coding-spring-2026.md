> Claude Opus 4.7 代码解决率飙升到 64.3%，Claude Design 发布当天 Figma 股价再跌 7%，一位全栈开发者用 AI 工具箱从零做出了好几个产品，Anthropic 官方 Skills 仓库一天涨 701 Star。五件事放在一起看，2026 年春天，"Vibe Coding"从概念真正变成了工具链。

---

## 一、从 Karpathy 的一句话到一个完整的工具箱

2024 年，Karpathy 提出了"Vibe Coding"这个概念——你不需要理解每一行代码，只要能把意图翻译给 AI，然后"感觉"着把产品做出来。

当时大多数人觉得这是天方夜谭。一个写了多年代码的全栈开发者在今天的掘金文章里坦诚："第一次听到这个词的时候我有点不屑。'不理解代码就上线'听起来像是灾难的前奏。"

但当他真的用这套工作流从零做出好几个项目之后，态度彻底变了。

今天，Vibe Coding 不再是一个哲学概念，而是一套**完整的工具链**：

| 环节 | 工具 | 作用 |
|------|------|------|
| 首席工程师 | Claude / Claude Code | 架构设计、代码生成、Debug |
| 设计 | Claude Design / Pencil | 从描述到设计稿到代码 |
| 后端 | Supabase | 数据库 + 认证 + API + 实时 |
| 邮件 | Resend | 注册验证、通知 |
| 部署 | Vercel | git push 即上线 |
| 版本控制 | GitHub | AI 代码的安全网 |

整条链路的核心变化是：**每一环都可以用自然语言驱动。** 你不需要手写数据库查询，不需要手配 Nginx，不需要从零搭邮件服务。你只需要说清楚"我要什么"，AI + 工具帮你搞定"怎么做"。

这就是 Vibe Coding 的本质——**把精力从"如何实现"释放到"要实现什么"。**

---

## 二、Claude 的扩张：从编程到设计到万物

Vibe Coding 能跑通，核心在于 Claude 这条"首席工程师"的能力在飞速进化。

### Opus 4.7：自我验证的"老员工"

4 月 17 日，Anthropic 在 Claude 降智危机后迅速推出 Opus 4.7（HN 1523 分），这一次不是挤牙膏，而是实打实的进化：

- **自我验证（Self-Verification）**：AI 在交活儿之前会先自己检查一遍。如果逻辑有漏洞，它会自己先改了，而不是直接把烂摊子甩给你
- **代码解决率飙升到 64.3%**：比上一代高出整整 10 个百分点
- **主动反问确认**：遇到模糊需求不再盲目瞎编，而是先问清楚
- **视觉升级**：支持长边最高 2,576 像素的图像，视力比以前好了 3 倍多

Anthropic 的描述很精准：以前它是个需要你手把手教的实习生，现在它已经能独当一面了。

### Claude Design：从写代码到做设计

如果说 Opus 4.7 让 AI 更会写代码，那 Claude Design（HN 877 分）则让 AI 开始"做设计"——发布当天 Figma 股价再跌 7%（4 月 15 日 Google Stitch 已让它跌过 12%）。

这不是一个工具的兴衰，而是一个时代的转折：**AI 对创意行业的冲击，从"辅助设计"进入了"替代设计"阶段。**

从 Copilot（副驾）到 Autopilot（自动驾驶），这个转变在编程领域已经发生了，现在设计领域正在重演。

### Skills 生态：从手搓到标准化

光有模型还不够。Vibe Coding 要跑通，还需要一个关键环节：**可复用的专业能力封装**。

Anthropic 官方 Skills 仓库正式发布（GitHub 701 stars/天），标志着 Skills 从社区自发走向了官方维护。Microsoft 也发布了 Agent Package Manager（apm），Agent 工具链进入包管理时代。

今天掘金上另一篇文章推荐了 11 个顶级 Claude Code Skills——代码审查、重构助手、单元测试生成——覆盖后端 Java、前端开发、DevOps 全栈。

Skills 的本质是给 AI 安装的"插件"或"技能包"。就像给一个新人入职时一套 SOP——遇到 A 情况怎么做，遇到 B 情况用什么工具。

**从"自己教 AI"到"安装 Skill 就行"，这是 Vibe Coding 从高手专属走向大众可用的关键一步。**

## 三、Vibe Coding 的阴暗面：繁荣之下的隐忧

但 2026 年春天的 Vibe Coding，不全是阳光。今天的热点池和知识沉淀日报里，至少有三条线索揭示了阴暗面。

### 隐忧一：算力瓶颈——Claude 半个月崩 7 次

Claude Opus 4.7 能力暴涨的代价是算力需求飙升。半个月内崩溃 7 次，背后是算力瓶颈暴露。强制实名制封号策略引发用户不满。

算力不足 + 用户增长 = 服务质量下降的恶性循环。当 Vibe Coding 从少数人的玩具变成大众的工作流，**算力正在成为第一个瓶颈。**

### 隐忧二：Vibe Coding 的反噬数据

Hermes Agent 那篇"劝你别急着追"的文章里，引用了一组触目惊心的数据：

| 指标 | 变化 |
|------|------|
| 代码 churn（改了又改的比率） | +41% |
| 代码重复度 | ×4 |
| 健康重构占比 | 从 25% 暴跌到 <10% |
| 安全公司测试 15 个 vibe coding 应用 | 69 个漏洞，6 个 Critical 级 |
| Apple 动作 | 已封禁多款 vibe coding 生成的应用 |

**AI 编程制造了一种效率幻觉——你觉得自己在飞速产出，但算上学工具的时间、调试 AI 行为的时间、修 AI 幻觉的时间，总成本反而更高。**

METR 的实验结论更直接：有经验的开发者使用 AI 工具后，实际完成任务反而慢了 19%。但他们自己觉得快了 20%。

### 隐忧三：框架疲劳

GitHub 上 ai-agent Topic 页面有 9,900+ 个仓库。2026 上半年至少有 25 个主流 Agent 框架进入过 Trending。每一个发布时都说自己是"唯一你需要的框架"，然后一个月后另一个冲上 Trending，上个月的"唯一"已经没人提了。

Reddit 上开始出现反趋势的帖子："I Stopped Using Frameworks"。这不叫技术进步，这叫**框架疲劳（Framework Fatigue）**。

## 四、如何在 Vibe Coding 时代活得好

在繁荣和隐忧之间，真正值得关注的不是"用什么工具"，而是"怎么用好工具"。

今天掘金上那篇 Vibe Coding 工具箱文章和 Hermes 那篇冷静分析，不约而同给出了同样的答案：

### 1. 规划和执行分离

Chrome 团队工程负责人 Addy Osmani 分享了他的 AI 编程工作流，里面没有一条是关于"选对框架"的，全是工程纪律：

- **先写 spec.md 做人工规划**，想清楚再让 AI 动手
- **拆小任务**，每个任务的边界清晰到 AI 不会"发挥"
- **超频 commit**，每个小步骤都提交，出问题能回滚
- **人类始终在监督位**，不要让 AI 无人值守跑 30 分钟

Stack Overflow 今年发布的 agents.md 规范指南，核心结论跟 Osmani 一样：**AI 放大的是你已有的工程纪律，不是替代它。**

### 2. 从八十分开始，别从零开始

与其让 AI 从零写 2000 行代码（3 处幻觉 API，改了一下午），不如用你的成熟模块搭好 80% 骨架，AI 只补最后 20% 的胶水代码（零幻觉，30 分钟合并）。

**框架会过时，但你的代码资产不会。**

### 3. 搞清楚你有什么

你的技术栈里有哪些成熟模块？哪些可以让 AI 直接复用？哪些有技术债需要先清理？如果这些问题你答不上来，换再多框架都是瞎折腾。

### 4. 建立框架无关的工程纪律

不管用 Hermes、OpenClaw 还是裸写 Claude Code，这些纪律不因框架而变：

- 规划和执行分离——人做规划，AI 做执行
- 控制任务粒度——每轮让 AI 做一件具体的事
- 超频 commit——每完成一小步就提交
- 写 spec 不写 prompt——与其花时间优化 prompt，不如花时间写清楚 spec.md

**这套流程，你用什么框架都适用。框架挂了，流程还在。**

## 五、写在最后

2026 年春天的 Vibe Coding，到了一个有趣的拐点。

工具链成熟了——Claude 做首席工程师，Supabase 做后端，Vercel 做部署，GitHub 做安全网。一个不懂代码的人，理论上已经可以做出一个能用的产品。

但工具链成熟不等于"随便做都行"。代码 churn 飙升 41%、69 个漏洞、Apple 封禁应用——这些数据在提醒我们：**Vibe Coding 降低的是入门门槛，不是质量标准。**

Karpathy 说的"感觉着编程"，前提是你能"感觉"出什么是对的。如果你连什么是好代码、好设计、好产品都感觉不出来，那"感觉着编程"只会产出"感觉着能跑但实际上千疮百孔"的东西。

**AI 时代缺少的不是技能，是想法，和快速验证想法的行动力。** 但验证想法的前提是，你有能力判断验证的结果好不好。

这才是 2026 年 Vibe Coder 真正的核心竞争力——不是你会用多少 AI 工具，而是你有多好的判断力。
